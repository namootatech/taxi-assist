# Voice guidelines (global)

**APD-Market.** Source of truth for user-facing language across Taxi Assist / Trip.  
**Principle:** Communicate **outcomes**, not systems.

---

## Copy hierarchy (always)

1. User benefit  
2. Emotional clarity  
3. Action clarity  
4. System detail — only when it helps the user act  

---

## Rules

- Human-first: sound like a helpful person, not infrastructure  
- No backend terms in UI (API, RPC, RLS, schema, sync jobs)  
- No robotic or “AI assistant” tone  
- Lead with what the user gets or what happens next  

---

## Tone by context

| Context | Tone |
|---------|------|
| Onboarding | Welcoming, simple, guiding |
| Errors | Calm, reassuring, solution-focused |
| Success | Positive, reinforcing |
| Dashboards | Minimal, clear |
| Marketing | Persuasive, emotional |

---

## Patterns

**Outcome vs feature**

- Avoid: “Manage driver onboarding workflow”  
- Prefer: “Get on the road and start earning”

**Human vs system**

- Avoid: “System completed processing request”  
- Prefer: “You’re all set”

**Action vs module**

- Avoid: “Vehicle module”  
- Prefer: “Add your vehicle”

---

## CTAs

**Default avoid:** Submit, Continue, Process, Execute (unless the flow truly needs a neutral advance).

**Prefer:** Get started, Join now, Start earning, Finish setup, Go live, Book a ride, Add payment method — verbs tied to the user’s goal.

---

## Errors

- Plain language first; no error codes as the headline  
- No blame  
- Offer a **next step** (retry, check connection, contact support)

Example: “Something went wrong. Try again — if it keeps happening, contact support.”

---

## Anti-patterns

- Explaining architecture or “how the platform works” in labels  
- SaaS filler: leverage, synergy, holistic solution  
- Passive lines with no clear action  

Users should feel **guided**, not processed.
